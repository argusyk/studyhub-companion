# Перенос endpoint

1. Знайти endpoint у legacy/ і описати його поведінку в docs/business-rules.md.
2. Написати характеризаційний тест, що фіксує поточну відповідь legacy-версії.
3. Реалізувати endpoint у apps/api за шарами router, service (шлях `/api/v1/...`).
4. Запустити характеризаційний тест проти нової реалізації.
5. Якщо тест падає, дозволено не більше трьох спроб виправлення. Після третьої
   невдачі зупинись, виклади гіпотезу про причину й попроси рішення людини.
6. Не змінюй характеризаційний тест, щоб він пройшов.
